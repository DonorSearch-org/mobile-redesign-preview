Интерактивный просмотрщик: https://donorsearch-org.github.io/mobile-redesign-preview/

**REVIEW_PENDING — NOT APPROVED.** Здесь только статические дизайн-прототипы и демонстрационные состояния. Это не frontend/backend DonorSearch и не сервис для ввода реальных донорских данных.

Восемь текущих вариантов: A / B / C / D / D-polish / E / E.1 / E.2. Более ранние интерактивные варианты сохранены в архиве. Прямые ссылки имеют вид `?version=site-2026-10-29-e2#/`; исторические каталоги не удаляются.

## Обычное обновление

1. В существующем приватном проекте просмотрщика создайте отдельную новую версию, сохраните прежние и выполните обычную Vite/React-сборку и её проверки. Исходники проекта в этот репозиторий не копируются.
2. Импортируйте проверенный `dist` в этот репозиторий:

   ```sh
   python3 .github/scripts/import-viewer.py --dist /path/to/verified-viewer/dist --archives /path/to/verified-viewer/public --source-revision VERIFIED_COMMIT
   python3 .github/scripts/check-site.py
   ```

   Импорт только адаптирует URL к базовому пути Pages. Он не меняет исходный просмотрщик и не удаляет старые файлы. Изменение уже сохранённого ресурса требует нового пути, чтобы прежние варианты продолжали выглядеть одинаково.
3. Проверьте новую версию локально под `/mobile-redesign-preview/`, включая изображения, шрифты, переключение и основные действия. Зафиксируйте проверенный статический пакет и опубликуйте в `main`.
4. Workflow `Publish design viewer` проверит manifest и выполнит штатный GitHub Pages deploy. После успешного Actions проверьте публичный URL; один зелёный workflow не заменяет публичную проверку.

В репозитории находятся `site/`, контрольный manifest и два небольших скрипта публикации. Здесь нет приватных исходников React, документов исследований, credentials, переписок, конфигурации Sites и Git-истории исходного проекта. Новые аккаунты и дополнительные сервисы не нужны.

## Воспроизведение локальной проверки

Сервер должен отдавать содержимое `site/` по пути `/mobile-redesign-preview/`, как GitHub Pages. Все версии используют hash-маршруты. Изменять приложение или делать SPA-redirect для этих маршрутов не требуется.

Проверки и измерения первоначального переноса описаны в `SIZE-REPORT.md` и `VERIFICATION.md`.
